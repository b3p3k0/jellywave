# Jellywave threat model

Status: 2026-10-30, describes plugin version 0.5.0.0 (cards 1–18 and Live Radio L1–L5, with the L7 rule
on `HttpContext.Items`, the L8 header for plain streams and the L6 titles for plain streams; release hardening R1 to R4:
settings writes, re-keyed ids, station call budgets, caches, receipt tokens, animated-image refusal, the page's refusal
handling and warnings, and the release workflow).
Written from the code and [`DESIGN.md`](DESIGN.md); where this file and the code disagree, the code
wins and this file is wrong.

Jellywave puts a "Live Radio" tile into Jellyfin: one channel holding one item per station. SUB/WAVE
stations get a poller that writes the current track and cover onto their items, and an optional
station page injected into jellyfin-web. Plain streams get a logo the plugin downloads, and the station page
shows a header for them too, with a website link and (card L6) the title the server samples from the stream
while someone plays it. Admins manage
the stations on the configuration page, which can probe a pasted address, and have two buttons that
write user policies. Each of those crosses a trust boundary.
This file says which ones, what holds them, and what is left open on purpose.

## Assets

| Asset | Why it matters |
|---|---|
| Jellyfin user sessions in jellyfin-web | The injected `ui.js` runs in the web client's origin with the signed-in user's session, admins included. Script injection there is account takeover. The configuration page's script runs in an admin's session and renders probe answers. |
| User policies (`EnabledChannels`, `BlockedChannels`) | The grant button and "Give them access to the renamed tile" write them, and only when an admin presses one. A wrong write shows the tile to someone the admin blocked, drops another setting, or undoes an admin's removal. |
| The station list | `Stations` in the plugin configuration: kind, URLs and format per station, and (card L8) genre, notes and a website link. It decides what the server fetches, what ffmpeg opens, what clients are told to play and which link every user of the tile is shown. |
| The earlier-name lists | `PreviousChannelNames` and `CarriedChannelNames`. Losing an earlier tile name lifts the blocks that name it; losing a carried name offers the carry-over again. |
| Stream URLs, plain streams' above all | Every stream URL is an ffmpeg input (every station is relayed since card L10), and Jellyfin still discloses it with its query, as the media source's `Path`, through PlaybackInfo and the channel items route (see Accepted risks). A plain stream's URL may carry a query, so an admin could put a secret there. |
| The station items and their images | The poller writes each item's description, name, sort name and Primary image (a cover or a logo). Other plugins' channels and the music library must not be touched. |
| The Jellyfin server's network position | The server calls SUB/WAVE stations, logo hosts, (card L6) the plain streams someone plays, and, for the probe, any address the admin pastes. A redirect or a crafted URL could turn that into requests to other hosts (SSRF). |
| Each station's request budget and identity | Every Jellyfin user shares one SUB/WAVE station's limits. |
| Request receipts | Map the server's own receipt token to the Jellyfin user who sent the request, the station (id and origin) it went to and the station's request id (card R2a); the accounting trail behind a free-text name. |
| Release artifacts and `manifest.json` | Users install from the manifest. A tampered zip or entry runs on every server that updates. |

## Trust boundaries

1. **Admin configuration is trusted.** Only an administrator can save it or call the admin routes
   (`POST /Jellywave/Probe`, `GET /Jellywave/Health`, `POST /Jellywave/Health/Check`, `POST /Jellywave/GrantAccess`, `GET` and
   `POST /Jellywave/CarryAccess`, `GET /Jellywave/Viewers`, `GET /Jellywave/WebUi`, all `RequiresElevation`).
   `GET /Jellywave/Viewers` (card L13) answers user names (the users who can see the tile but have audio
   transcoding off), so it stays on the admin controller; a real-pipeline test checks that a signed-in
   non-admin gets 403 for it and every other admin route, and that the user store is not read. The configuration is
   still validated, so a mistake fails closed: a station whose URL breaks the rules is not listed, with
   the reason on the page, and the other stations are listed regardless.
   - **The probe fetches what the admin pastes and what stations choose** (card L3). Check sends one
     headers-only request to the pasted address. It then follows addresses it did not get from the
     admin: a playlist's first http(s) entry (any host and port, loopback and LAN included), up to four
     `/api/state` reads under the address's origin and directory, the feed, and a SUB/WAVE feed's
     stream mount. **Any address that is not audio is also tried as a SUB/WAVE base URL.** What comes
     back reaches only the admin who pressed Check, but it can tell that admin something about a host
     the server can reach: the HTTP status ("not reachable: HTTP 404"), whether something answers like
     SUB/WAVE (`Kind`), and its base URL. Admin-only, bounded (below), and listed under "Accepted
     risks".
2. **Station and logo-host responses are untrusted data.** The hosts are admin-chosen but their answers
   are not trusted. These controls cover the plugin's own requests (feed, state, schedule, likes,
   requests, lyrics, covers, portraits, plain-stream logos, plain-stream title samples, the probe), not the
   audio stream played, which Jellyfin's ffmpeg (or, for a static request, Jellyfin's own HTTP client) fetches:
   - Bodies are bounded: 256 KB for JSON and playlists, 4 MB for images. Time: 8 s per JSON call, body included;
     images and playlists 8 s for the headers plus 8 s for the body. A title sample (card L6) reads no body
     without an `icy-metaint` from 1 to 64 KiB, then exactly that many audio bytes, one length byte and at most
     255 × 16 metadata bytes (never more than metaint + 1 + 4080), all under one 8 s budget, and closes at once:
     the plugin's client drains no unread body (`MaxResponseDrainSize = 0`; .NET's default would read up to 1 MB more
     for up to 2 s to reuse the connection; checked on a real socket).
   - The plugin follows no redirect on its own requests. Its named HTTP client has `AllowAutoRedirect = false`;
     a 3xx is the answer, mapped to a failure, "no art", or (probe) a suggestion the admin must accept.
   - Images are sniffed. The type comes from magic bytes (JPEG, PNG, GIF, WebP), the size from the
     header (at most 4096 px a side, 16 777 216 px area); anything else is "no art" or a failed logo.
     The declared content type only has to be missing or `image/*`.
   - Ids that go back into station URLs (cover, persona, song, request) must be 1–64 characters of
     letters, digits, `_` and `-`.
   - Every address a station or playlist names (a playlist entry, a feed's stream mount, a redirect
     target the probe shows) passes the same URL rules as the admin's own before any request or display.
   - Text written to an item's description is whitespace-collapsed and cut at 120 characters per field.
     Jellyfin's own clients render that description under their own rules. A plain stream's description is
     its notes (card L8): admin text, or `icy-description` text Check filled in (so a third party's words), one
     line, cut at 280, with every `<` and `>` dropped (`JellywaveChannel.StreamOverview`): jellyfin-web renders an
     overview as sanitized HTML and Markdown, so no tag reaches it. Markdown needs no angle brackets, though: a
     `[text](https://…)` link or a bare address in the notes can still render as a clickable link in Jellyfin's
     detail view, which the website rule does not cover. The station page shows the notes as plain text.
     An idle SUB/WAVE station's description (card L14) is its Tagline, which Check can fill from the station's
     DJ tagline (a third party's words), else its notes (`JellywaveChannel.IdleOverview`): one line, cut at 280,
     with every `<` and `>` dropped; the same Markdown-link remark applies.
   - A sampled title (card L6) is a third party's text, shown as sent (HI: no filtering): decoded as UTF-8 or
     Latin-1, the `StreamTitle` field parsed without trusting its quoting, control characters turned into spaces,
     whitespace collapsed, cut at 200 characters (`StationText.Clean`). It is kept in memory only, never written to
     an item, and the page shows it through `textContent` and `innerText` only.
   - Check reads `icy-genre`, `icy-description` and `icy-url` (card L8) and offers them in the dialog, cleaned
     like `icy-name` and cut to the limits; `icy-url` gets `http://` in front when it has no `://`, then the
     website rule (below). They are saved only when the admin presses Add or Apply and Save.
3. **Stream URLs go to ffmpeg, and clients can read them.** The plugin builds each item's media source
   from the station list; since card L10 every station is relayed (`SupportsDirectPlay=false`, no
   `EncoderPath`, no client URL), so no client is told to fetch a station. `Path` is `Uri.AbsoluteUri`,
   so the URL reaches Jellyfin's `-i "<url>"` escaped (see Controls), and clients can still read it
   (PlaybackInfo, the channel items route; see Accepted risks). What ffmpeg then does with the stream (it
   follows redirects and fetches HLS segments from other hosts), and what Jellyfin's own HTTP client does for a
   static request (it follows redirects too), is outside the plugin's client.
4. **Jellyfin users must be signed in and able to see the channel. One gate for many stations.** Every
   station route (Stations, Feed, Avatar, Like GET and POST, Schedule, Lyrics, Request POST, Request/{id},
   and since card L6 Title) carries `[Authorize]` and `[StationAccess]`. The filter refuses a block on an
   earlier tile name (rename bridge), then runs Jellyfin's own `Channel.IsVisible(user)`: block list,
   enabled list or `EnableAllChannels`, then parental controls. Administrators get no exemption. A missing
   or colliding channel fails closed with 404. A user who passes can use every SUB/WAVE station in the tile
   (HI decision); Jellyfin has no per-item visibility for channel items. The gate covers the plugin's own
   routes only: Jellyfin's channel items and stream routes do not ask it, so tile access hides the tile but
   does not lock it (see Accepted risks).
5. **A station route reaches a station only through `[StationRoute]` and `CallerStation()`.** After the
   gate, the `[StationRoute]` action filter resolves the caller's `stationId` (absent: the primary
   station, for older cached pages) to a listed SUB/WAVE station, else 404 with no station asked. The
   actions read it only through `CallerStation()`, which throws without the filter. A request's status
   goes to the station in its receipt, never one the caller names. `GET /Jellywave/Stations` lists every
   listed station (card L8: plain streams too, with their kind) with ids, names, Jellyfin item ids, image
   tags and the header fields (notes; a plain stream's genre, format and website link), never a stream or
   station URL. A plain stream with a blank name is named after its stream URL's host (card L11; the host only,
   never its port, path or query, here and in the admin's Health), which its item name shows every user of the tile
   anyway. A plain stream's id in that list still answers 404 on every SUB/WAVE station route. The one
   route that takes a plain stream's id, `GET /Jellywave/Title` (card L6), goes through the filter's
   plain-stream variant (`[StationRoute(PlainStream = true)]`): only a listed plain stream resolves (a SUB/WAVE,
   disabled, refused, unknown or missing id is 404), the filter leaves only its id (`PlainStation`), and the
   action reads the sampler's state through `CallerPlainStation()`; it never samples and answers no URL. An IL
   scan of the controller (and of `StationList`) enforces the rule; see Controls.
6. **API keys are refused on station routes.** Jellyfin's default policy lets any API key through;
   the filter answers 403 unless the `Jellyfin-IsApiKey` claim is present and parses as false.
7. **The pages render station text as text.** The station page's header markup is one of two fixed strings
   (a SUB/WAVE station's header, a plain stream's header); every station-supplied value (track, DJ, tagline,
   show, recent tracks, lyrics, schedule, request outcomes, the playing bar's lines, station and tile names in
   the header, the playing bar and the drawer link, genre, notes, the format line, a plain stream's sampled title
   in the "Now:" line, the playing bar and the media session) goes in through `textContent`, a
   created element's `textContent`, or `innerText`. Images are Jellyfin image URLs built from the item id
   and tag, or a blob URL of the portrait fetched with the session. The page talks only to the Jellyfin
   server, never to a station. The configuration page puts station and probe text into `textContent` or
   an input's `value` only.
8. **The website link is admin-set, shown to every user of the tile, and never fetched** (card L8). A station's
   `Website` is typed by the admin or filled by Check from the stream's `icy-url` header (so a station can
   suggest it; the admin sees it in the dialog before saving). The server never requests it: it is read only by
   `StationList` for `GET /Jellywave/Stations`, through `StationUrls.WebsiteLink`, the website rule: absolute
   `http` or `https` with a host IDNA accepts (`Uri.IdnHost`; a host it refuses, such as one with U+2028, is
   refused), served with the punycode host so a look-alike Unicode host shows as `xn--…`, no userinfo (`@`
   before the path, not even an empty one), at most 2048 characters as typed and as escaped (`Uri.AbsoluteUri`);
   anything else is dropped there and the station stays listed. The page checks again (`WEBSITE_RULE` in
   `ui.js`: `http://` or `https://`, an ASCII host or an IPv6 literal, an optional port, then printable ASCII
   only, so no whitespace, control character or userinfo) before the value becomes an `href`, so a `javascript:`
   or `data:` value never does. Only a station the list calls `SubWave` gets the SUB/WAVE routes from the page;
   a missing or unknown kind gets the plain header, which asks nothing. The link opens in a new tab with
   `rel="noopener noreferrer"`: the opened page gets no `window.opener` and no `Referer` naming the Jellyfin
   server.
9. **The anonymous assets are static.** `ui.js` and `ui.css` are embedded in the DLL and served
   without sign-in (the page needs them before sign-in); they carry no data.

## Accepted risks

| Risk | Why it is accepted |
|---|---|
| **One gate for many stations** | Every user who can see the tile can use every station in it, including every SUB/WAVE station's page, likes and requests. Jellyfin has no per-item visibility for channel items (HI decision). The README and the configuration page say so. |
| **Stream URLs disclosed to clients, query included** | Every stream URL is its item's media source `Path`. Jellyfin returns it to any API key and to signed-in users: through `Items/{id}/PlaybackInfo` to a user who can see the item (`Channel.IsVisible` included), and through `/Channels/{id}/Items?fields=MediaSources` to every signed-in user, the tile hidden or not (next row). Relay only (L10) does not hide it: no client is told to fetch the station any more, but any of them can read the URL the server reads. A plain stream's query is allowed (HI decision), so it is disclosed the same way. The README and the plugin page (a warning under Stations, and on Check for a query parameter named like a secret, R2b) say never to put secrets in stream URLs. SUB/WAVE streams are public; listener auth is not supported. |
| **Tile access hides the tile but does not lock it** (D6) | Jellyfin works this way for all media, not only Jellywave. Unticking the tile for a user, or a block on its current id (also one "Give them access to the renamed tile" copied), hides it from My Media and `/Channels`, and `/Items/{id}` and PlaybackInfo answer 404. But `GetChannelItems` checks no visibility, so any signed-in user can list the channel's items with their stream URLs (`/Channels/{id}/Items?fields=MediaSources`; the channel id comes from the tile name) and stream them (`/Audio/{id}/stream`), and `/Audio/{id}/stream` answers with no sign-in at all (`AudioController` has no `[Authorize]`; listed in jellyfin/jellyfin#5415, closed as a duplicate; still true in 12.4). An item id is computable: MD5 of UTF-16LE (type full name + external id + channel name + "16") (`ChannelManager.GetIdToHash`, `LibraryManager.GetNewItemId`). Since R2a station ids are random (the public `live` and starter ids are re-keyed once), so item ids cannot be guessed, but any signed-in user can read them and pass them on. The plugin cannot close the signed-in part: answering no items for one user makes Jellyfin delete the items for everyone. The `/Jellywave/*` routes do check access (403). Host test on 12.4, 2026-10-30. The plugin page says so under Stations (R2b). |
| Blocks cannot be managed in Jellyfin 12.3 and 12.4 | A policy save ignores `BlockedChannels` (`UserManager.UpdatePolicyAsync`; host test on 12.3, 2026-10-28; 12.4 changed only the .NET runtime), so neither the dashboard nor the policy API can set or clear a block. Existing blocks stay, including the ones "Give them access to the renamed tile" copies onto the new tile, and removing one takes a database edit. An admin cannot hide the tile from one user with a block; unticking the tile on the user's Access page is the only per-user control, and it hides the tile without locking it (row above). The plugin honours blocks on earlier tile names for as long as they exist. |
| After a failed configuration load, earlier tile names are unknown | The plugin runs on defaults in memory and cannot know the real old tile name, so a user blocked from it sees the (empty) tile: no station, no content, no station data. The unreadable file is never written over: it is copied aside first (the page names the copy), and while that copy fails every save is refused. The configuration page warns until a save works. A failed *migration* keeps old blocks. |
| **The probe's station-chosen requests** | Check follows no redirect, but a pasted playlist names the address it checks next (any host and port, loopback and LAN included, headers only), and any address that is not audio is also tried as a SUB/WAVE base (`/api/state`). The answer can show the admin the HTTP status of an internal address, whether it answers like SUB/WAVE, and its base URL. Every request goes through the plugin's client (no redirect, 8 s, 256 KB) and the probe stops after eight requests or 30 s. Only an admin can run it, and an admin can already make the server fetch any URL by saving it as a station. |
| **Stream redirects and HLS segments followed by Jellyfin** | Jellyfin fetches the stream, not the plugin's client, and follows redirects: ffmpeg for client playback (its http input follows up to 8, `max_redirects` in libavformat's `http.c`, which Jellyfin does not set), and Jellyfin's default `HttpClient` for a static request (`/Audio/{id}/stream?static=true`, `AudioHelper` → `FileStreamResponseHelpers.GetStaticRemoteStreamResult`; `NamedClient.Default` keeps `AllowAutoRedirect` on). A station that redirects its stream can point either at another host, and an HLS playlist names its segments on any host. "Redirects refused" is the plugin's own client only. The plugin cannot change how Jellyfin fetches a stream; the admin chooses the station, and Check shows a redirect of the pasted address. |
| Plain-HTTP station URLs | SUB/WAVE normally runs on plain HTTP on the LAN, and many radio streams are plain HTTP; refusing it would break the common install. |
| **Starter stations contact public hosts by default** (L9) | A fresh install lists five public stations, each with a random id since card R2a (fixed ids made every install's item ids the same), until the admin removes them: the server fetches each starter logo once per start, whether or not anyone listens, and asks the SUB/WAVE demo for now playing only while someone plays it or has its station page open (card L14; before it, every update interval around the clock), and those hosts see the server's address and its User-Agent (`Jellywave/<version> (+project URL)`). One starter streams over plain HTTP across the internet (WRUW, which has no https form; WJCU uses its https address, HI 2026-10-29), so a network attacker on the path could change its audio or titles, as for any http station; titles reach the page as text only. The README names the starters, what they contact, and how to remove them. Upgrades get none. |
| Name-derived channel id | Jellyfin's plugin API has no other channel identity. A collision with another plugin's channel fails closed and shows on the configuration page. A rename is bridged (earlier names kept, old blocks honoured, one press carries grants and blocks), not accepted. |
| **Old cover tag after a restart, or after a station is removed and re-added** (L4) | The image-tag rule compares the item's applied cover origin with the station's current one, and that memory is in-process. After a restart (when a station's URL changed while the server was down), or after a station is removed and re-added under the same id with another URL, the plugin does not know which origin the item's saved cover came from, so `Feed` and the station list can serve the old cover's tag until the next poll's write phase replaces it (at most one poll, plus the fetch phase). The image is a track cover the item already showed; no URL is involved. |
| **Limits of the IL scan** (L5, narrowed by S-b) | The scan and its allow-list walk read IL, so they cannot see what runs outside the code they follow: a delegate whose target was made elsewhere (a `Func<object>` handed in by DI); plugin code the framework builds and calls without a token in the walked code (an HTTP handler or JSON converter registered at startup, or named by an attribute such as `[JsonConverter]`, since attributes are not IL); a framework virtual call (`ToString`, `Dispose`) on a plugin object the walk neither constructs nor hands on, which is not fanned out to every plugin override; and a station value that other code writes into shared state of a non-station type (a static `string` or `object`) and a listed member hands back as a plain value. Reflection or dynamic code through names neither the deny rules nor the walk's sinks cover would pass. The bodies of the three `Items` accessors are not checked for writes. A new allow-list line is a review decision: the walk proves what a listed helper reaches, not that its reason is true. The reflection walk over held types and the behaviour tests (every route against unlisted ids, the loopback pipeline) would catch a station mix-up. |
| **One ffmpeg per listener, unthrottled** (L10) | Every listener is a separate ffmpeg re-encode on the server (AAC 256 kbps HLS for the web client) with its own connection to the station, and the plugin limits neither. Any user who can see the tile can start one per session, and any signed-in user, or anyone with an item id and no sign-in, can start more through `/Audio/{id}/stream`, one per request (a static request opens a server connection to the station instead; row "Tile access hides the tile"). HI: nothing is throttled; the README gives the per-listener cost so a small server can plan. Jellyfin's own per-user settings (Dashboard → Users → the user → Profile; jellyfin-web 12.4 `Profile.tsx`, `en-us.json`): "Allow media playback" (`EnableMediaPlayback`; 12.4 reads it only in `BaseItem.GetPlayAccess`, so it tells clients to hide Play and the server does not check it), "Allow audio playback that requires transcoding" (`EnableAudioPlaybackTranscoding`; off, PlaybackInfo offers nothing playable, so clients cannot play stations), "Maximum number of simultaneous user sessions" (`MaxActiveSessions`, checked at sign-in) and "Internet streaming bitrate limit (Mbps)" (`RemoteClientBitrateLimit`, clients outside the local network). They act at sign-in and in PlaybackInfo; on the stream routes the transcoding setting only forces stream copy for a signed-in user, so none of them refuses a direct `/Audio/{id}/stream` request. |
| Shared station identity and request budget | Each SUB/WAVE station sees the server as one caller, so its own request limit (SUB/WAVE: 1 per 20 s, 8 an hour) is shared by every user. Since card R2a (D10) each user may send at most 1 request a minute and 4 an hour across all stations, so one user alone can no longer spend the whole hour's station budget at once, but two users together still can; the station's own lower limit still wins. The page explains it. |
| **Station load driven through the server** | Since card R2a: bounded, not removed. Each user may cause 60 station calls a minute, refused ones included (a station's refusal keeps the general slot spent), likes 10 a minute and requests 1 a minute and 4 an hour; at most 4 calls are in flight per station, 16 in all and 4 portraits; lyrics, portraits, like status and request status are answered from caches (one fetch per key however many users ask). What is left: several users together, each within their 60 a minute, can still keep one station at its 4 in-flight calls (each bounded by the 8 s budgets and the body caps), and while they do, other users of that station get 503 with `Retry-After` for a moment; across stations they share 16 slots. Budgets live in memory and reset on restart. `Feed` answers from the poller's state and `Schedule` from a five-minute cache. The users are signed-in Jellyfin users who can already see the tile. |
| **A website link can point anywhere on http or https** (L8) | Every user of the tile sees a plain stream's website and can open it. The admin sets it, or accepts what Check filled from the stream's `icy-url`; the admin is trusted and sees the value before saving. The plugin limits it to an http or https link without credentials, never fetches it, and the link opens without `window.opener` or a `Referer`. What the linked site does is outside the plugin. |
| **Title samples are outbound requests driven by playback** (L6) | While any user plays a plain stream, the server opens that stream every 15 s and reads up to metaint + 1 + 4080 bytes (at most about 68 KiB, at most 8 s): users decide when the server connects, but only to admin-listed streams, one sample per stream per round however many listen, and nothing while nobody plays. Any session's now-playing report counts if its user (or an added user) can see the tile (L14 fix round 2), from any client, including a crafted `POST /Sessions/Playing` by such a user who is not listening: still only admin-listed streams, still one sample per stream per 15 s, and nothing comes back to that user but the title the Title route would show anyway. The admin can switch sampling off with "Show what's playing". The station sees an extra short listener (README note) from the server, which relays it anyway. A stream that redirects is not followed and shows the delayed text. |
| **Sampled titles are a third party's text** (L6) | HI: shown as sent, no filtering; the admin is responsible for the stations added. Bounded and cleaned (above), rendered as text only, kept in memory, never written to an item or a log. A station can still put any words or a link-like string in its title. |
| Free-text DJ name | A listener can type any name the DJ will see. The real user id is kept in the receipt and the log line, so abuse can be traced. |
| User-save window against dashboard saves (Phase 5 D3) | Only while a grant or carry-over pass is running: a change to a user that lands between the plugin's read and save of that user (milliseconds) is overwritten, because the plugin saves the whole user (`UpdateUserAsync`: `SetValues`, `SyncPermissions`) and `IUserManager` has no partial update. That can undo any change to that user saved in that moment (a dashboard save, a password change, a lockout after failed sign-ins), not only channel access: an old password hash can come back, or a lockout be lifted. The admin sees the old value on reload and saves again. |
| New users are not granted automatically | Since card 15b nothing grants in the background. The dashboard's Add User page leaves "Enable access to all channels" unticked, so a user added there, from a template or by a provisioning tool cannot see the tile until the admin ticks it or the tile, the tool's template includes it, or the button is pressed again. The safe direction: a missing grant hides the tile. |
| A press re-adds the tile to users an admin unticked | The grant button adds the channel to everyone who cannot see it, and an unticked user looks the same as one never granted. Only a `BlockedChannels` entry survives, and jellyfin-web has no screen for it. The press is an explicit admin action, and the page says to untick those users again afterwards. |
| Item whole-row write racing Jellyfin's channel refresh | Jellyfin has no partial item update. Narrowed: images are downloaded first, then the item is looked up and written; every poll reconciles each item's text, name, sort name and image. |
| Image structure walk limits (R2a) | Animated GIF, APNG and animated WebP are refused, and so is a JPEG with more than 100 scans (no longer an accepted risk: a small file could carry many frames or scans for Jellyfin's image processor, and only the first frame was sized). What stays: the walk reads structure, not pixels, so one well-formed still image of 4096 × 4096 is still decoded in full by Jellyfin (the size limits above), up to 100 progressive scans are decoded, and PNG CRCs and the compressed data are not checked (Jellyfin's decoder sees them). |
| jellyfin-web DOM selectors | `.itemsContainer[data-parentid]`, `.nowPlayingBar` and `.card` are jellyfin-web internals that can move between releases; when one moves, the page is meant to do nothing rather than break the client. |
| Receipt store full (R2a) | No user's receipt is evicted for another's any more: at most 20 per user (their own oldest goes), and when 1000 are held a user who owns none is refused (503) before the station is asked. With the per-user request budget (4 an hour) that needs 250 users requesting within half an hour. |
| Receipts lost on restart | Receipts live in memory; a request pending across a restart shows "lost track". |
